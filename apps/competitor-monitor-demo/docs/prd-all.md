---

## 1. 问题与目标

**问题：** 运营无法系统、周期性看到竞品在小红书上围绕品牌词的笔记投放结构（量级、达人层级、内容话术），只能靠手工搜帖。

**目标：**
1. 在 A3 内配置竞品品牌、多品牌词、抓取频次、单次上限、达人分层阈值。
2. 系统按周期自动抓取小红书笔记（默认时间排序）。
3. 详情页提供笔记清单 + 走势 / 达人金字塔 / 词云三块看板。

---

## 2. 角色与权限

| 角色 | 能力 |
|------|------|
| 运营 / AE（Demo：林运营） | 新建/编辑/删除竞品、查看详情看板 |
| 后端调度 | 按频次抓取、写入笔记与聚合（本 Demo 不实现） |
| 管理员 | 菜单权限（产品 monorepo；Demo 固定侧栏） |

Demo 不做登录与权限矩阵。

---

## 3. 信息架构

```
A3 顶栏（投放洞察）
└── 侧栏「竞品监控」
    ├── 竞品列表
    │   └── 新建 / 编辑 Modal（配置）
    └── 竞品详情
        ├── 配置摘要
        ├── 看板：走势 | 达人金字塔 | 词云
        └── 笔记表
```

侧栏「热帖追踪」仅为占位，标明与本功能并列、本 Demo 不实现。

---

## 4. 界面清单与验收

| # | 界面 | 谁用 | 必须行为 |
|---|------|------|----------|
| 1 | 竞品列表 | 运营 | 看到品牌、词、频次、上限、状态、上次更新、笔记数；可搜索 |
| 2 | 新建/编辑 | 运营 | 必填品牌、≥1 品牌词、频次、上限、分层阈值；可启用开关 |
| 3 | 详情看板 | 运营 | 三块看板 + 笔记表；可返回列表；可编辑配置 |
| 4 | 产品文档 | 研发/AI | 顶栏入口可预览/下载 MD |

---

## 5. 关键业务规则

1. MVP 平台固定为**小红书**；排序默认**时间倒序**。
2. 频次：`weekly` / `biweekly`（默认 biweekly）。
3. **单次抓取上限**按「每个品牌词」配置，竞品级可不同。
4. **达人分层阈值**按竞品独立配置：粉丝 `< bottom` 底部；`[bottom, mid)` 中腰；`≥ mid` 头部。
5. 多品牌词分别搜索，按 `note_id` 去重合并。
6. 互动量定义：**赞 + 藏 + 评**（不含分享，除非后续产品变更）。
7. 停用（关闭启用）后不再调度；历史笔记仍可查看。

# 产品需求 · 列表与配置

| 项 | 内容 |

| 文档状态 | 与当前 Demo 对齐 |

---

## 1. 问题与目标

**问题：** 缺少统一入口管理「盯哪些竞品、用哪些词、多久抓一次、抓多少、怎么分层」。

**目标：**
1. 列表一眼看到监控任务健康度与规模。
2. 配置项足够支撑后端调度，且**每个竞品可不同**。

---

## 2. 列表字段

| 列 | 说明 |
|----|------|
| 竞品品牌 | 点击进详情 |
| 品牌词 | Tag 展示 |
| 抓取频次 | 每一周 / 每两周 |
| 单次上限/词 | 数字 |
| 状态 | 已更新 / 抓取中 / 失败 / 已停用 |
| 上次更新 | 本地时区展示（产品用业务时区） |
| 笔记数 | 去重后累计或最近批次（Demo 用累计） |
| 操作 | 查看 / 编辑 / 删除 |

工具栏：搜索品牌 +「新建竞品」主按钮。

---

## 3. 配置表单（Modal）

| 字段 | 必填 | 规则 | 默认 |
|------|------|------|------|
| 竞品品牌 | 是 | 非空字符串 | — |
| 品牌词 | 是 | ≥1；回车或「添加」；可删 | — |
| 抓取频次 | 是 | weekly / biweekly | biweekly |
| 单次抓取上限/词 | 是 | 整数 10–500 | 100 |
| 底部达人阈值 | 是 | 粉丝 `<` 该值 → 底部 | 10000 |
| 中腰部达人阈值 | 是 | 须 `>` 底部；`≥` 该值 → 头部 | 500000 |
| 启用自动抓取 | 否 | 开关 | 开 |
| 平台 | — | MVP 固定小红书，只读 | 小红书 |

**分层公式：**  
`fans < bottom` → 底部；`bottom ≤ fans < mid` → 中腰；`fans ≥ mid` → 头部。

---

## 4. 界面验收

| # | 必须行为 |
|---|----------|
| 1 | 无数据时空态文案 + 可新建 |
| 2 | 未填品牌或品牌词时不可保存 |
| 3 | 中腰阈值 ≤ 底部时不可保存并提示 |
| 4 | 删除需二次确认（Demo：危险色确认钮；产品：antd danger + Modal.confirm） |
| 5 | 编辑后列表与详情摘要同步 |

---

## 5. 关键业务规则

1. 品牌词按用户输入原样保存（不去空格语义改写）。
2. 修改分层阈值后，已有笔记应按新阈值重新计算分层（Demo 已做）。
3. 修改上限/频次从**下一调度周期**生效（后端契约）；Demo 仅存配置。

---

## 6. 非目标

- 批量导入竞品
- 品牌词同义词库

# 产品需求 · 详情与看板

| 项 | 内容 |
|----|------|
| 产品 | A3 SaaS · 竞品投放监控 |
| 文档状态 | 与当前 Demo 对齐 |
| Demo | 详情页三块看板 + 笔记表 |

---

## 1. 问题与目标

**问题：** 只有笔记流水不够决策；需要看到量级走势、达人结构、内容话术分布。

**目标：**
1. 摘要区复述配置与规模。
2. 三块看板：走势、达人金字塔、词云。
3. 下方笔记明细可核对。

---

## 2. 页面结构

1. 顶栏：返回 · 品牌名 · 状态 ·「编辑配置」
2. 摘要：品牌词 / 频次+上限 / 笔记数 / 互动合计
3. 看板区：
   - 左：走势图（笔记数 + 互动量，双轴）
   - 右：达人金字塔（底 / 中 / 头）
   - 下：内容词云（标题+正文）
4. 笔记表：时间、标题、作者、粉丝、分层、赞/藏/评、匹配词

---

## 3. 看板定义

### 3.1 走势

| 项 | 定义 |
|----|------|
| 横轴 | 抓取批次时间（Demo 用模拟双周点） |
| 纵轴左 | 该批次笔记数 |
| 纵轴右 | 该批次互动量（赞+藏+评） |
| 空态 | 尚无批次时展示空图或提示 |

### 3.2 达人金字塔

| 层 | 规则 |
|----|------|
| 底部 | `fans < tierBottomMax` |
| 中腰 | `tierBottomMax ≤ fans < tierMidMax` |
| 头部 | `fans ≥ tierMidMax` |

展示：每层篇数 + 占比。阈值文案在卡片标题旁展示。

### 3.3 词云

- 语料：笔记标题 + 正文（后端分词；Demo 用预设词权）
- 字号映射词频权重
- MVP 不做点击下钻

---

## 4. 界面验收

| # | 必须行为 |
|---|----------|
| 1 | 从列表点品牌名或「查看」进入详情 |
| 2 | 金字塔层数与当前分层配置一致 |
| 3 | 编辑配置改阈值后返回详情，分层标签更新 |
| 4 | 无笔记时笔记表空态，看板不假装有真实抓取 |

---

## 5. 关键业务规则

1. 详情只读本竞品数据，不做多品牌对比。
2. 互动合计与走势「互动量」口径一致：赞+藏+评。
3. 匹配词：笔记命中的品牌词之一（多词命中时后端可返回数组；Demo 单值）。

---

- 导出 Excel（可后续）

# 产品需求 · 后端交接契约

| 项 | 内容 |
|----|------|
| 产品 | A3 SaaS · 竞品投放监控 |
| 文档状态 | 与当前 Demo 对齐（前端 mock；供后端实现） |
| 受众 | 后端、前端对接、测试 |

> 本 Demo **不实现**调度与抓取。下列为产品侧约定，供后端落地与联调。

---

## 1. 核心对象

### CompetitorMonitor（竞品监控任务）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 主键 |
| brand | string | 竞品品牌名 |
| keywords | string[] | 品牌词，≥1 |
| frequency | `weekly` \| `biweekly` | 抓取频次 |
| limit_per_keyword | int | 每个品牌词单次上限，建议 10–500 |
| tier_bottom_max | int | 底部上限（不含）：fans &lt; 此值 |
| tier_mid_max | int | 中腰上限（不含）：fans &lt; 此值；≥ 为头部 |
| enabled | bool | 是否调度 |
| platform | const `xiaohongshu` | MVP 固定 |
| sort | const `time_descending` | MVP 固定时间排序 |
| status | enum | `idle` / `running` / `updated` / `failed` / `paused` |
| last_run_at | datetime? | 上次调度结束 |
| last_success_at | datetime? | 上次成功 |
| note_count | int | 去重笔记数（展示用可缓存） |
| created_by / tenant_id | — | 按 A3 多租户模型 |

### Note（笔记）

| 字段 | 类型 | 说明 |
|------|------|------|
| note_id | string | 平台笔记 ID，去重键 |
| competitor_id | string | 归属任务 |
| title / desc | string | 标题 / 正文 |
| author_name | string | 作者昵称 |
| author_id | string? | 作者 ID |
| fans_count | int | 粉丝数（抓取时快照） |
| liked_count / collected_count / comment_count | int | 互动 |
| published_at | datetime | 笔记发布时间 |
| matched_keywords | string[] | 命中的品牌词 |
| crawled_at | datetime | 入库时间 |
| batch_id | string | 所属抓取批次 |

### CrawlBatch（批次）

| 字段 | 说明 |
|------|------|
| id | 批次 ID |
| competitor_id | 任务 |
| started_at / finished_at | 时间 |
| status | success / partial / failed |
| note_count | 本批新增或 upsert 数 |
| engagement_sum | 本批笔记互动合计 |
| error_message | 失败信息 |

---

## 2. 调度规则

1. 仅 `enabled=true` 且状态非人工暂停的任务入队。
2. `weekly`：距 `last_success_at`（或创建时间）≥ 7 天触发；`biweekly` ≥ 14 天。
3. 每个 `keyword` 独立请求搜帖，`limit_per_keyword` 为停止上限；共同去重规则见数据源能力。
4. 排序：时间倒序；不在本 MVP 暴露其他 sort UI。
5. Upsert：同一 `note_id` 更新互动与粉丝快照，保留首次 `crawled_at`。
6. 分层不落死标签也可：读时用任务当前 `tier_*` 计算（改阈值立即生效）。

---

## 3. 聚合 API（建议）

供详情看板：

| 接口意图 | 返回 |
|----------|------|
| GET 任务详情 | 配置 + 摘要计数 |
| GET 批次走势 | `[{ date, note_count, engagement }]` |
| GET 分层分布 | `{ bottom, mid, top }` 篇数 |
| GET 词云 | `[{ term, weight }]`（后端分词） |
| GET 笔记分页 | 表字段 + 计算后的 tier |

写接口：创建/更新/删除任务；可选「立即跑一次」（权限另定）。

---

## 4. 数据源假设

- 小红书关键词搜帖（如 TikHub `xiaohongshu` + `time_descending`）。
- 费用与 QPS 由后端按 `limit_per_keyword × keywords.length` 估算并做租户配额。
- 抓取失败：任务 `status=failed`，详情可展示最近错误；不删历史笔记。

---

## 5. 前端 Demo 对应关系

| Demo 字段 | 契约字段 |
|-----------|----------|
| limitPerKeyword | limit_per_keyword |
| tierBottomMax | tier_bottom_max |

# 设计规格 · 竞品社媒投放监控（A3 SaaS 演示层）

| 项 | 内容 |
|----|------|
| 产品 | A3 SaaS · 竞品投放监控 |
| 平台 | Web（桌面优先，列表/表单可在窄屏纵向堆叠） |
| 实现层 | **演示层**：静态 HTML + `a3-*` + Font Awesome；产品落地用 antd Layout / ProTable |
| 文档状态 | 与当前 Demo 对齐 |

---

## 1. Purpose Statement

让运营在 A3 内配置竞品品牌与品牌词，按自定周期与抓取上限拉取小红书笔记，并在详情页用走势、达人金字塔、词云判断竞品投放结构——不是舆情告警，也不是热帖榜。

## 2. Aesthetic Direction

**A3 SaaS 工作台**：粉系主色、浅灰内容底、白底 PageContainer、侧栏信息架构。  
覆盖 ui-design-guide 默认禁令的原因：本功能嵌入已有 A3 品牌与组件规范（主色 `#c9677d`、演示字体栈含 PingFang SC / 系统 UI）。

明确不做：紫系渐变、玻璃拟态、居中落地页式营销排版、emoji 图标。

## 3. Color Palette

| Token | 值 | 用途 |
|-------|-----|------|
| `--a3-primary` | `#c9677d` | 主按钮、链接、选中、图表主系列 |
| `--a3-primary-light` | `#fff8f0` | 选中行/菜单背景 |
| Tabs 并存强调 | `#dc8249` | 顶栏系统 Tab 激活（壳层） |
| `--a3-danger` | `#ff4d4f` | 删除确认 |
| `--a3-bg-body` | `#F0F2F5` | 内容区底 |
| `--a3-bg-card` | `#FFFFFF` | 列表/看板容器 |
| 金字塔：底/中/头 | `#E8B4BE` / `#c9677d` / `#8B3A4A` | 达人分层 |

## 4. Typography

演示层沿用 `a3-components.css`：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。  
字号：页标题 16–18px / 正文 14px / 辅助 12px。

## 5. Layout Strategy

```
Header 48px（Logo + 系统 Tabs 近似 + 产品文档 + 用户）
└── Sider 200px + Content
    ├── 竞品列表（默认）
    └── 竞品详情（PageContainer：配置摘要 | 看板三块 | 笔记表）
```

- 列表：工具栏「新建竞品」+ 表 + 操作列（查看 / 编辑 / 删除）
- 新建/编辑：居中 Modal（品牌、品牌词、频次、单次抓取上限、达人分层阈值）
- 详情：上摘要条 → 看板三模块纵向 → 笔记表格；返回列表

## 6. Motion

- Modal / 抽屉：200ms ease-out 淡入
- 菜单选中：背景与右边框切换，无弹跳
- 走势图：首次进入详情时折线描边短暂绘制（CSS/SVG）

## 7. Prototype Scope

可点：列表 CRUD 本地态、详情看板与笔记、顶栏「产品文档」。  
不可点/mock：真实 TikHub 抓取、登录鉴权、权限菜单生成。
