## 1. 问题与目标

**问题：** 用户自建 MCP（业务 API 以 tools 暴露给 Agent）时，平台缺少统一视图回答：调了哪些 tool、谁调的、从哪家客户端、成没成、耗时多少。

**目标：**
1. 提供平台管理员向的「网关请求台」（方案 A）：总览 KPI → 调用流水 → 详情抽屉 → 工具档案。
2. 一行 = 一次 `tools/call`；列必须含 **谁** + **哪工具**（+ 平台、状态、时间、延迟）。
3. Demo 可切换「我的调用」用户 stub（更轻页面）；默认管理员台。
4. 不接真实 MCP 后端；不做 Trace 树（方案 B out of scope）。

## 5. 总览 KPI 口径

**范围（所有 KPI 共用）：** 总览时间窗（近 24h / 7d / 30d）。Demo **无环境筛选**，统计全量 mock。  
事件粒度：一行 = 一次工具调用（`tools/call`）。

### 5.1 白话（与 UI `?` 一致）

| KPI | 说明 |
|-----|------|
| **调用数** | 选定时间窗里，一共发生了多少次工具调用。 |
| **错误率** | 失败调用占全部调用的比例。失败指报错或超时（不含用户取消）；没有调用时按 0% 显示。 |
| **P95 延迟** | 把时间窗内所有调用耗时从小到大排好，取排在大约 95% 位置上的那个耗时。意思是约 95% 的调用不慢于该值，只有最慢约 5% 更慢。 |
| **活跃工具** | 时间窗里至少被调用过一次的不同工具有多少个。 |

### 5.2 技术备注（给 AI / 研发，可选）

| KPI | 实现口径 |
|-----|----------|
| 调用数 | `count(events in range)` |
| 错误率 | `failed / total × 100%`；`failed` = `status ∈ {error, timeout}`；`canceled` 不计入；`total=0` → `0%` |
| P95 延迟 | 范围内全部调用的 `duration_ms` 升序后取第 95 百分位（`ceil(0.95 × n)` 位） |
| 活跃工具 | `distinct tool_name` 且该工具在范围内 ≥1 次调用 |

UI tip：`app.js` → `KPI_FORMULAS`（白话）。

## 6. 关键业务规则

1. **粒度：** 一行 = 一次 `tools/call`（非 Session / Trace）。
2. **谁：** Demo 用 `caller_label` + `caller_user_id` + `tenant` + `api_key_id`。
3. **Payload：** **Demo 默认展示完整参数/结果 JSON**（真实形态 mock，无掩码），便于评审；生产可另做脱敏/二次权限。
4. **session_id / trace_id：** 字段可空，UI 明示空；不做树。
5. **环境：** Demo 不提供顶栏环境切换；事件可带 `environment` 字段仅详情展示。
6. **Mock：** 静态生成事件；刷新不请求网络。
